Peer Onboarding & Antigravity Engineering

Complete collaboration guide for peers: repository access, Antigravity AI pair-programming, PostgreSQL, and production releases.

Invite Collaborator on GitHub
01

Step 1: Accept GitHub Invite & Clone Repository

Private repository authorization & initial local environment

Once the repository owner invites you via GitHub Collaborators, accept the invitation and clone the project to your local workspace using your GitHub account credentials or Personal Access Token (PAT): 

# Clone the repository:
git clone https://github.com/LaudzaFarhan/training-center.git
cd training-center

# Install project dependencies (Express, PostgreSQL client, Dotenv):
npm install
02

Step 2: Launch Google Antigravity & AI Pair-Programming

Leverage Antigravity Agent Mode, Inline Edits, and Planning

Open the training-center folder in Google Antigravity IDE. Antigravity integrates directly with this codebase and follows our established brand identity and database architecture:

  • Agent Mode (Sidebar Chat): Use for complex multi-step tasks, creating new REST APIs, database queries, and architectural refactoring.
  • Inline Modality (Ctrl + I): Highlight any function or component to instantly refactor, fix, or document without leaving the editor.
  • Interactive Alignment (/grill-me): Type /grill-me in chat when planning a feature to align on design decisions before code execution.
  • Live Share (Real-time Pair Programming): Install the Live Share extension to code simultaneously with your peers inside Antigravity with shared terminal and cursor presence.
03

Step 3: Environment Setup (.env) & PostgreSQL

Configuring local environment variables and database migrations

Copy the template environment configuration. The application will automatically run schema migrations and seed the default admin account: 

# 1. Create your local .env file from the example:
cp .env.example .env

# 2. (Optional) If running PostgreSQL locally, create database:
sudo -u postgres psql -c "CREATE DATABASE thelab_training;"

# 3. Start local server (Runs at http://localhost:3050):
npm start
04

Step 4: Git Branching & Pull Request Workflow

Safe team development protocol without breaking production

Always create a dedicated feature branch for your work. Never push unfinished experiments directly to main: 

# Create and switch to your feature branch:
git checkout -b feature/trainee-reports

# Develop your feature with Antigravity, then commit:
git add .
git commit -m "feat: add downloadable attendance report"

# Push branch to GitHub and create a Pull Request (PR):
git push -u origin feature/trainee-reports
05

Step 5: Production VPS Deployment Protocol

Shipping verified features to training.thelabindonesia.my.id

Once your Pull Request is reviewed and merged into main, deploy to the production VPS in 2 commands: 

# On your production VPS (SSH):
cd /var/www/training-center
git pull
pm2 restart thelab-training
